**Status:** Initial Specification  
**Website:** https://saelvostudio.github.io/

**Hosting:** GitHub Pages  
**Budget:** ₹0  
**Core Technologies:** HTML5, CSS3, and JavaScript

---

# 1. Product Overview

## 1.1 Vision

16:01 Studio is a premium personal portfolio website showcasing graphic design, illustration, printing art and visual communication work through a distinctive, modern, editorial digital experience.

The website must communicate creativity, professionalism, and strong visual identity while presenting projects in an engaging, organized, and accessible manner.

It must not resemble a generic portfolio template. Instead, it should feel like an independent creative studio with carefully art-directed layouts, bold typography, high-quality artwork, and purposeful interactions.

## 1.2 Product Objective

Create a professional portfolio website that:

- Establishes a recognizable creative identity.
- Showcases graphic design and illustration projects.
- Presents detailed project case studies.
- Communicates the designer's skills and services.
- Encourages professional inquiries and collaborations.
- Provides an excellent experience across desktop, tablet, and mobile devices.
- Allows new projects to be added without rebuilding the entire website.
- Remains free to host and maintain using GitHub Pages.

## 1.3 Core Principle

**The artwork is the hero. The interface exists to make the artwork more compelling.**

Typography, layout, color, animation, and interactions must support the creative work rather than compete with it.

## 2.2 Creative Agencies

# 4. Brand Identity and Visual Direction

## 4.1 Brand Name

16:01 Studio

## 4.2 Professional Title

Graphic Designer & Illustrator

## 4.3 Brand Personality

The visual identity should communicate:

- Creativity.
- Confidence.
- Precision.
- Independence.
- Contemporary design.
- Editorial sophistication.
- Visual experimentation.
- Professionalism.

## 4.4 Visual Design Direction

The website should combine:

- Minimalist composition.
- Bold editorial typography.
- Strong visual hierarchy.
- Generous whitespace.
- Large-scale artwork.
- Carefully controlled asymmetry.
- Restrained color usage.
- Subtle transitions.
- Consistent spacing and alignment.

Avoid generic gradients, unnecessary decorative elements, excessive rounded cards, and animations that distract from the artwork.

## 4.5 Color Palette

The initial color palette is:

| Color | Hex Value | Purpose |
|---|---|---|
| Dark background | `#111310` | Primary canvas |
| Primary text/warm off-white | `#F5F2EB` | Headlines and body text |
| Dark black | `#111111` | Selected sections |
| Warm gray secondary | `#B0ADA5` | Supporting information |
| Burnt red accent | `#C64B35` | Highlights and interactive details |
| Dark gray border | `#34352F` | Dividers and outlines |
| White | `#FFFFFF` | Selected image surfaces |

The palette may be refined during visual design, provided the overall identity remains consistent and text contrast is sufficient.

## 4.6 Typography

The typography system should include:

- Bold display typography for primary headlines.
- A highly readable sans-serif for body text.
- Clear differentiation between headings and supporting information.
- Compact, legible project metadata.
- Optional expressive serif typography for selected editorial elements.

Fonts must have appropriate licenses and reliable fallback options.

## 4.7 Layout Principles

- Use a consistent content grid.
- Maintain generous margins and spacing.
- Allow project layouts to vary according to the artwork.
- Preserve image proportions unless intentional cropping is required.
- Use large images for important projects.
- Avoid unnecessary visual clutter.
- Maintain consistency across pages without making every section identical.

# 7. Project Content Requirements

Project content should be organized so that adding new projects does not require rebuilding the entire website.

## 7.1 Project Data Fields

Each project should support:

| Field | Description |
|---|---|
| ID | Unique project identifier |
| Slug | URL-friendly project identifier |
| Title | Project name |
| Category | Primary project category |
| Categories | Additional applicable categories |
| Year | Project year, when relevant |
| Thumbnail | Project preview image |
| Hero Image | Main case-study image |
| Alt Text | Descriptive image alternative |
| Summary | Short project description |
| Role | Designer's contribution |
| Featured | Whether to feature the project |
| Published | Whether the project is publicly visible |
| Sections | Flexible case-study content |

## 7.2 Project Content Management

The initial website does not require a content-management system.

Projects may be managed using JavaScript data files and individual HTML case-study pages.

Adding a project should involve:

1. Preparing and optimizing the artwork.
2. Adding image files to the assets directory.
3. Adding the project information.
4. Creating or updating the case-study page.
5. Testing links and image paths.
6. Publishing the changes.

The process must be documented in the project README.

# 8. Motion and Interaction Requirements

Motion should enhance the presentation without distracting from the work.

## 8.1 Required Motion

- Subtle hero entrance.
- Selected scroll-reveal effects.
- Restrained project hover interactions.
- Navigation hover transitions.
- Clear button feedback.
- Smooth category-filter interactions.
- Optional subtle image transitions.

## 8.2 Optional Advanced Motion

After the core website is complete, optional enhancements may include:

- Subtle parallax.
- Image reveal masks.
- Project-specific transitions.
- Carefully controlled horizontal galleries.
- Interactive illustration details.
- Desktop cursor-following effects.

These features must remain optional.

## 8.3 Motion Restrictions

- Respect reduced-motion preferences.
- Do not force scrolling.
- Do not block navigation.
- Do not hide essential content until animations complete.
- Avoid excessive parallax.
- Avoid unnecessary cursor replacement.
- Keep mobile interactions simple.
- Do not sacrifice performance for visual effects.

All essential website content must remain accessible when animations are disabled.

# 11. Image and Asset Requirements

## 11.1 Image Quality

- Use appropriate source resolutions.
- Optimize images before uploading.
- Preserve artwork quality.
- Avoid unnecessary enlargement of low-resolution assets.
- Generate suitable thumbnails.
- Use descriptive filenames.
- Maintain intended image proportions.

## 11.2 Recommended Formats

- WebP or AVIF for suitable photographic and raster artwork.
- PNG for images requiring transparency.
- SVG for suitable vector illustrations, logos, and icons.
- WOFF2 for self-hosted web fonts where applicable.

## 11.3 Loading Strategy

- Lazy-load images below the initial viewport.
- Prioritize the main hero image.
- Specify image dimensions or aspect ratios.
- Avoid loading full-size case-study assets unnecessarily on the homepage.
- Use responsive images when beneficial.

## 11.4 Licensing

Only publish artwork, fonts, mockups, and other assets that the designer is authorized to use.

Respect applicable licenses and client confidentiality requirements.

Required practices include:

- Semantic HTML landmarks.
- Logical heading hierarchy.
- Meaningful image alternative text.
- Sufficient text contrast.
- Keyboard-accessible navigation.
- Visible focus indicators.
- Descriptive control labels.
- Reduced-motion support.
- Appropriate touch-target sizes.
- No essential hover-only interactions.
- No essential information communicated solely through color.

Accessibility must be reviewed through manual testing and automated checks.

# 23. Risks and Mitigation

## Excessive Animation
**Risk:** Motion distracts from the artwork.

**Mitigation:** Complete the layout first and add only purposeful effects.

## Inconsistent Artwork Quality
**Risk:** Different image quality and presentation reduce visual cohesion.

**Mitigation:** Prepare consistent thumbnails, image sizes, and presentation rules.

## Overcomplicated Architecture
**Risk:** Unnecessary files and dependencies make maintenance difficult.

**Mitigation:** Use lightweight HTML, CSS, and JavaScript.

## Broken Deployment Paths
**Risk:** Assets work locally but fail on GitHub Pages.

**Mitigation:** Verify paths and test the production deployment.

## Weak Project Context
**Risk:** Visitors cannot understand the purpose of the work.

**Mitigation:** Provide concise project summaries, the designer's role, and relevant process details.

## Nonfunctional Contact Form
**Risk:** Visitors submit inquiries that never reach the designer.

**Mitigation:** Use a verified email link unless a tested submission service is configured.

## Missing Content
**Risk:** The website appears unfinished.

**Mitigation:** Prioritize the strongest available projects and publish only verified professional information.
