# 1. Project Overview

## 1.1 Project Vision

Design a distinctive, premium-quality portfolio website for 16:01 Studio, representing a graphic designer and illustrator.

The website must function as both a professional portfolio and an immersive digital presentation of creative work.

The experience should combine editorial art direction, bold typography, carefully composed layouts, high-quality artwork, subtle interactions, and a recognizable visual identity.

The website must not look like a generic portfolio template, a standard agency website, or a conventional developer portfolio.

It should feel like an independent creative studio with a strong visual point of view.

## 1.2 Primary Objective

Create a website that enables visitors to:

- Immediately recognize the 16:01 Studio identity.
- Understand the designer's creative disciplines.
- Explore graphic design and illustration projects.
- Examine detailed project case studies.
- Understand the designer's creative approach.
- Discover relevant services.
- Initiate professional inquiries.

## 1.3 Core Design Principle

**The work is the centerpiece. The interface is the frame.**

Every design decision must enhance the presentation of the artwork.

Typography, spacing, animation, navigation, color, and interactive elements should work together to create a memorable experience without competing with the projects themselves.

# 5. Visual Design Direction

## 5.1 Overall Aesthetic

**Primary style:** Premium editorial minimalism.

**Supporting influences:**
- Contemporary graphic design publications.
- Independent creative studios.
- Art-directed portfolio websites.
- Experimental typography.
- Gallery-style artwork presentation.
- Modern print and editorial design.

The result should feel sophisticated and visually expressive rather than decorative for its own sake.

## 5.2 Composition

Use:

- Large typographic statements.
- Strong alignment.
- Generous negative space.
- Asymmetrical project grids.
- Oversized artwork.
- Carefully controlled overlap.
- Full-width visual moments.
- Variable image proportions.
- Clear separation between content sections.

Do not force every section into the same grid.

Each project may have its own composition, but all pages must belong to the same visual system.

## 5.3 Whitespace

Whitespace is a fundamental design element.

Use it to:

- Separate content groups.
- Emphasize important artwork.
- Improve readability.
- Create rhythm between sections.
- Give typography room to breathe.
- Make the interface feel deliberate.

Avoid both excessive empty space that makes the website feel unfinished and dense layouts that reduce the artwork's impact.

## 5.4 Borders and Dividers

Use thin, subtle dividers to establish structure where useful.

Possible applications:

- Header boundaries.
- Project metadata.
- Section introductions.
- Footer columns.
- Editorial indexes.

Borders should support the composition rather than become decorative noise.

## 5.5 Shapes and Decorative Elements

Prefer typography, lines, image masks, and layout relationships over excessive decorative shapes.

Any additional graphic element should have a clear role in the brand identity.

# 6. Color System

| Token | Color | Hex | Purpose |
|---|---|---|---|
| Background | Dark background | `#111310` | Main canvas |
| Primary text | Warm off-white | `#F5F2EB` | Headlines and body text |
| Dark background | Deep black | `#111111` | Selected sections |
| Secondary text | Warm gray | `#B0ADA5` | Supporting information |

| Border | Dark gray | `#34352F` | Dividers and outlines |
| White | White | `#FFFFFF` | Selected image surfaces |

These colors establish the initial direction and may be refined during implementation.

## 6.2 Color Usage Rules

- Off-white should dominate the primary interface.
- Near-black should provide strong contrast.
- The accent color should be used selectively.
- Dark sections should create intentional visual contrast.
- Project artwork should retain its original colors.
- Interactive states must remain accessible.
- Text contrast must be tested.

## 6.3 Accent Applications

The accent color may be used for:

- Small navigation indicators.
- Selected category filters.
- Underlines.
- Arrows.
- Small graphic details.
- Availability indicators.
- Selected interactive states.

Avoid coloring every button, link, and decorative element with the accent.

# 7. Typography System

Typography is one of the most important components of the website's identity.

## 7.1 Typography Direction

Use a bold editorial display typeface paired with a highly readable sans-serif.

An expressive serif may be introduced for selected editorial moments if it strengthens the overall identity.

## 7.2 Typography Hierarchy

| Level | Purpose | Suggested Treatment |
|---|---|---|
| Display H1 | Primary hero statement | Oversized, bold, tightly spaced |
| H2 | Major section headings | Large and confident |
| H3 | Project titles and subsections | Medium to large |
| Body | Descriptions and introductions | Comfortable and readable |
| Metadata | Category, year, role | Compact and understated |
| Navigation | Primary navigation | Clear and restrained |
| Microcopy | Small labels and annotations | Small but legible |

## 7.3 Suggested Fluid Type Scale

These values are starting points rather than fixed requirements.

| Element | Suggested Size |
|---|---|
| Hero heading | `clamp(3rem, 8vw, 8rem)` |
| Section heading | `clamp(2rem, 4vw, 4.5rem)` |
| Project title | `clamp(1.25rem, 2vw, 2rem)` |
| Body text | `1rem–1.125rem` |
| Metadata | `0.75rem–0.875rem` |
| Navigation | `0.875rem–1rem` |

Actual sizes must be adjusted according to the selected font, layout, and screen size.

## 7.4 Typography Rules

- Use tight line spacing for large headlines where appropriate.
- Keep body text comfortable to read.
- Avoid excessively long text lines.
- Use letter spacing intentionally.
- Avoid too many typefaces.
- Maintain a clear distinction between headings and supporting text.
- Ensure headings wrap naturally on mobile devices.

## 7.5 Font Licensing

Use fonts with appropriate licenses.

Free font families such as Inter, Manrope, or Space Grotesk may be evaluated for the sans-serif system.

The final selection must prioritize the brand's character, readability, and reliable loading.

# 8. Layout and Grid System

## 8.1 Desktop Grid

Use a flexible multi-column grid.

Suggested starting points:

- 12-column grid for larger editorial layouts.
- Flexible two- and three-column project arrangements.
- A consistent maximum content width.
- Responsive outer margins.
- Variable image spans.
- Clear section alignment.

Not every section must use all 12 columns.

## 8.2 Tablet Grid

The tablet layout should simplify desktop compositions while retaining the visual identity.

Requirements:

- Reduce the number of project columns when needed.
- Preserve artwork proportions.
- Adjust outer margins.
- Prevent narrow text columns.
- Maintain comfortable spacing.

## 8.3 Mobile Grid

The mobile layout should prioritize readability and artwork visibility.

Requirements:

- One-column project layout where appropriate.
- Reduced horizontal margins.
- Simplified navigation.
- Fluid typography.
- Clear separation between projects.
- No unintended horizontal scrolling.
- Comfortable touch targets.

## 8.4 Suggested Breakpoints

| Device | Approximate Width |
|---|---|
| Small mobile | 320–374 px |
| Mobile | 375–767 px |
| Tablet | 768–1023 px |
| Desktop | 1024–1439 px |
| Large desktop | 1440 px and above |

Layouts must be tested at intermediate widths as well.

# 11. Work / Projects Page UI/UX

## 11.1 Objective

Provide a structured browsing experience for the complete portfolio.

## 11.2 Required Elements

- Page heading.
- Short introduction.
- Category filters.
- Project grid.
- Project titles and metadata.
- Links to case studies.

## 11.3 Category Filter Design

Filters should appear as a clear horizontal list, compact button group, or typographic index.

The active filter must be distinguishable through more than color alone.

### Interaction Requirements

- Clicking a category filters the projects.
- The selected category is visually identified.
- All Work restores every published project.
- Keyboard interaction is supported.
- Filtering does not unexpectedly move focus.
- Project layout remains stable and readable.

## 11.4 Project Grid

The grid should balance visual variety and browsing clarity.

Do not use identical card layouts for every project if varied compositions improve the presentation.

However, project titles, categories, and navigation behavior should remain consistent.

## 11.5 Empty and Loading States

Because the portfolio is static, loading states should be avoided unless genuinely necessary.

Categories with no published projects should generally be omitted.

The page must not display broken image placeholders or misleading project counts.

# 16. Interaction Design System

## 16.1 Buttons

Buttons must have consistent:

- Typography.
- Spacing.
- Shape.
- Hover state.
- Focus state.
- Active state.

Use button-like styling selectively.

Links should remain recognizable as links.

## 16.2 Links

Provide clear feedback through:

- Underlines.
- Color changes.
- Small directional movements.
- Arrow transitions.

Avoid interactions that make the link destination unclear.

## 16.3 Project Cards

Use restrained image movement or subtle visual feedback.

The card should communicate interactivity without requiring elaborate animation.

## 16.4 Navigation

Provide:

- Default state.
- Hover state.
- Focus state.
- Active state where applicable.

Mobile navigation must support keyboard and touch interaction.

## 16.5 Category Filters

Provide:

- Default state.
- Hover state.
- Focus state.
- Selected state.

Selected states must remain identifiable without relying solely on color.

## 16.6 Interaction Timing

Suggested starting points:

| Interaction | Duration |
|---|---|
| Small hover feedback | 150–200 ms |
| Button transitions | 150–250 ms |
| Image transitions | 250–400 ms |
| Subtle entrance animation | 300–600 ms |

Durations should be refined according to the visual effect.

Avoid long animations that delay interaction.

# 17. Motion Design Brief

## 17.1 Motion Philosophy

Motion should communicate hierarchy, reveal information, and create continuity.

It must not exist simply to demonstrate technical complexity.

## 17.2 Required Motion Treatments

### Hero Reveal
Subtle entrance for the primary heading and supporting content.

### Project Hover
Small image-scale or position changes.

### Scroll Reveal
Selected sections may reveal as they enter the viewport.

### Navigation Feedback
Short transitions for links and controls.

### Image Transitions
Subtle opacity or clipping transitions where appropriate.

## 17.3 Optional Experimental Motion

- Carefully controlled parallax.
- Image reveal masks.
- Horizontal project galleries.
- Project-specific motion studies.
- Interactive illustration details.
- Desktop cursor-following elements.

These are optional enhancements.

## 17.4 Motion Restrictions

- Respect reduced-motion settings.
- Avoid forced scrolling.
- Avoid excessive parallax.
- Avoid long loading sequences.
- Do not block navigation.
- Do not hide essential information until an animation completes.
- Keep mobile interactions lightweight.

The design should follow WCAG 2.2 Level AA principles wherever practical.

## Requirements

- Sufficient color contrast.
- Readable font sizes.
- Semantic heading hierarchy.
- Keyboard-accessible navigation.
- Visible focus indicators.
- Descriptive alternative text.
- Appropriate button and link labels.
- Reduced-motion support.
- Touch-friendly controls.
- No reliance on color alone.
- Clear visual feedback for interactions.

## Usability Principles

- Make the next action obvious.
- Keep navigation consistent.
- Avoid unnecessary decision points.
- Keep project information concise.
- Make important controls easy to locate.
- Ensure interactions behave predictably.

# 21. Image and Artwork Presentation

## 21.1 General Requirements

Artwork is the primary visual content and must be treated as such.

Images must:

- Display at suitable sizes.
- Preserve intended proportions.
- Avoid unnecessary cropping.
- Maintain acceptable sharpness.
- Use optimized formats.
- Load efficiently.
- Have appropriate alternative text.

## 21.2 Image Backgrounds

The interface must accommodate artwork with different background colors.

Do not automatically place every image on the same background if doing so harms the presentation.

Use image frames, background surfaces, or padding selectively.

## 21.3 Mockups

Mockups may be used when they help communicate the intended application of a design.

They must not replace the original artwork when direct viewing is important.

Avoid excessive mockup usage that makes the portfolio feel repetitive.

## 21.4 Asset Consistency

Prepare project thumbnails with suitable proportions and visual quality.

The project grid should feel cohesive without forcing every artwork into an identical crop.

14. The design can be implemented within the approved technical constraints.
15. The visual system remains consistent across all pages.

# 27. Final Design Direction

16:01 Studio should feel like a carefully art-directed digital publication created by an independent graphic designer and illustrator.

Its visual identity should be defined by:

- Warm off-white and near-black foundations.
- A restrained accent color.
- Bold editorial typography.
- Generous negative space.
- Distinctive project compositions.
- Large-scale artwork.
- Clear navigation.
- Purposeful motion.
- Accessible interactions.
- Responsive layouts.

The design should feel expressive without becoming chaotic, minimal without becoming empty, and experimental without sacrificing usability.

**Final UX objective:** Create an experience that immediately establishes the designer's identity, makes the artwork compelling to explore, communicates professional capabilities, and encourages meaningful contact.
